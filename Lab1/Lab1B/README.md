# Задание 2. Вариант 1. Индекс текстовых документов

Самостоятельный проект C++14 по образцу итогового задания 1 из Desktop/Labs/OOP/Lab1A. Тексты документов читаются целиком из .txt, включая несколько строк. В консоли вводятся ID и путь, а не сам текст. Файлы сохраняй в UTF-8, допускается BOM.

## Запуск

В PowerShell перейди в эту папку:

```powershell
.\build.ps1
.\text_index.exe
```

Нужен g++. В Visual Studio можно открыть папку как CMake-проект или создать консольный проект и добавить четыре .cpp и заголовки. Включи /utf-8 и C++14. Для обычного проекта рабочий каталог отладки — $(ProjectDir); папки documents и test_data должны находиться рядом с проектом. CMake копирует эти папки в каталог сборки.

Меню такое же, как в задании 1:

- 1 — автоматические тесты;
- 2 — ручное использование;
- 3 — готовый пример;
- 0 — выход.

Есть аргументы --test и --demo. Ручной режим позволяет добавлять файлы, удалять документы по ID, искать одно слово или все слова запроса, показывать индекс. Возврат в главное меню сохраняет ручные данные до закрытия программы. Тесты и пример используют отдельные объекты.

Пример добавления:

```text
ID документа: 1
Путь к txt-файлу: documents/document1.txt
```

Относительный путь считается от рабочего каталога программы. Можно ввести полный путь и путь с пробелами; внешние двойные кавычки убираются. Для переносимого запуска примеров используются латинские имена файлов. При ошибке открытия выводится сообщение, ручное меню продолжает работать. Для тестов и примера в рабочем каталоге должны быть соответствующие папки данных.

## Как устроена программа

| Файл | Ответственность |
|---|---|
| Document.h/.cpp | ID документа, чтение всего файла и хранение текста |
| BinaryTree.h | Собственное дерево поиска с параметрами Key, Value, Compare |
| Intersection.h | Общий шаблонный алгоритм пересечения с правилом Equal |
| TextIndex.h/.cpp | Выделение слов, индексирование, поиск и удаление документов |
| Console.h | Ввод числа с проверкой диапазона и ввод строки |
| Tests.h/.cpp | Объявления и реализации require, runTests и проверки файлов |
| main.cpp | Меню и демонстрация через публичные методы модели |
| documents/ | Три документа готового примера |
| test_data/ | Файлы тестов; invalid-utf8.txt намеренно содержит неверную кодировку |

Обычные реализации разделены на .h и .cpp. Шаблоны остаются в заголовках, чтобы компилятор видел их при подстановке типов. require реализована в Tests.cpp без inline. В main вызывается std::system("chcp 65001 > nul"), как в итоговом задании 1. windows.h и условные платформенные блоки не используются.

Путь обработки: Document(id, fileName) читает весь файл через ifstream и ostringstream, убирает начальную метку BOM; TextIndex проверяет ID и выделяет слова; дерево хранит пары «слово — список ID». Поиск всех слов пересекает списки через intersection. Удаление убирает ID из всех записей и удаляет слова с пустым списком.

Русские и латинские буквы приводятся к нижнему регистру; поддерживаются ё и цифры. Остальные символы разделяют слова: C++17 даёт c и 17. Буквы е и ё различаются. Повторы слова не дублируют ID.

Документ хранит снимок текста на момент загрузки. После изменения файла удали документ из индекса и добавь заново. Удаление из индекса не удаляет и не меняет .txt. Индекс хранится в памяти, между запусками не сохраняется.

## Соответствие методичке

Основа: «ООП Лабораторные ТОП-ИТ 1 Лаб v1.pdf», задание 2, вариант 1, печатные страницы 20–22.

- Предметная модель, хранение, алгоритм пересечения и вывод разделены.
- Собственное дерево поддерживает insert, find, contains, erase, inorder. Готовых map/set нет.
- Дерево не знает о документах: ключ, значение и сравнение задаются шаблоном. Проверены целочисленные ключи и обратный порядок std::greater.
- Каждый ключ уникален. Все ключи слева предшествуют узлу, справа следуют за ним по Compare. Вставка дубликата возвращает false и сохраняет прежнее значение.
- Корнем владеет дерево, потомками — родитель через unique_ptr. Обычные указатели временно наблюдают за объектами. find возвращает указатель на значение или nullptr; после удаления соответствующего узла этот указатель использовать нельзя.
- Симметричный обход возвращает пары в порядке Compare. getIndex отдаёт снимок записей и не открывает доступ к узлам.
- intersection применим к другим типам; проверен на числах, строках и с переданным правилом равенства.
- Пустой запрос и неизвестное слово дают пустой результат. Повторы слов в запросе не дублируют результаты.
- Готовый пример загружает три .txt с общими словами и повтором слова кот в первом файле. Показывает индекс, существующее/отсутствующее слово, запрос кот код, удаление, повторный поиск и обход.

## Проверки

Автотесты проверяют пустое дерево, вставку, дубликаты, поиск, удаление листа/узла с одним и двумя потомками/корня, преемника с правым потомком, точный порядок и значения после удаления, обратное сравнение и повторное использование дерева.

Для индекса проверяются регистр, русские/латинские буквы, цифры, отсутствие дублей, уникальность ID, однословный и многословный поиск, пустые результаты, удаление последнего документа для слова и полная очистка.

Для файлов проверяются несколько строк, пустой файл, BOM, пробелы в имени, отсутствующий файл, неверный UTF-8 и неизменность исходного файла после удаления из индекса. Ошибки открытия и кодировки не меняют прежний индекс. Выполняются 63 проверки require, включая числа и повторы из твоего примера по алгоритмам.

## Связь с твоей работой по деревьям

Основа сверена с Header.h и Source.cpp из Desktop/Labs/AlgosLab/Lab5. Сохранены отдельная структура Node, класс BinaryTree, связи root/left/right, текущий узел curr в цикле вставки и рекурсивный inorder с накоплением результата в vec. Как и в твоём коде, публичный inorder создаёт вектор, вызывает внутренний обход от root и возвращает вектор.

Что пришлось адаптировать под условие ООП:

- Вместо одного int value узел хранит Key key и Value value; типы задаются шаблоном.
- В твоём insert очередь находила первое свободное место по уровням. Для дерева поиска направление выбирает Compare: меньший ключ — влево, больший — вправо. Повтор ключа отклоняется.
- Владение через new/delete и clear заменено на знакомый по первому заданию unique_ptr: дерево автоматически освобождает узлы.
- Добавлены обязательные для индекса find, contains и erase. Для удаления рассматриваются лист, один потомок и два потомка.
- Суммы, высоты и виды дерева из лабораторной по алгоритмам здесь не хранятся: индекс ими не пользуется.

Реализация шаблонов находится в .h, поскольку должна быть видна при подстановке конкретных типов. Проверка на исходном наборе 70, 50, 30, 60, 40, 20, 80, 150 возвращает отсортированные пары; повторные 50 и 70 не создают новых узлов.

Старые PDF в общей папке output/pdf описывают прежнюю версию второго задания со строковым вводом. Для этой версии актуальны исходники и эта инструкция.
